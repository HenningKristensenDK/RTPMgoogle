## How to work on this project (IMPORTANT)
- Edit code ONLY in Claude Code running inside PowerShell (terminal), never the desktop app Code tab (that runs in a sandbox that cannot reach this machine or deploy).
- After changes: npm run build && firebase deploy --only hosting --project rtpm--v2
- Then commit and push: git add . / git commit / git push origin claude/epic-feynman-wx9jhf
- GitHub is the single source of truth. Ranjith now actively collaborates as a developer via his own VS Code + Claude Code setup, pushing directly to `claude/epic-feynman-wx9jhf` (not `main` — `main` is still just the original scaffold commit and has none of the real app; there is no merged PR yet, decide with Henning when/whether to open one).
- **First-time setup on a new machine (Ranjith or anyone else):** `git checkout claude/epic-feynman-wx9jhf` (not main) → `npm install` → copy `.env.example` to `.env` and fill in the Firebase web config (Console → Project settings → your web app) **plus `VITE_GEMINI_API_KEY`** (this key is required or AI chat throws immediately — it was missing from `.env.example` until 2026-07-03, now fixed) → `npm run dev`. `.env` and `serviceAccountKey.json` are gitignored on purpose and never travel with `git pull` — `serviceAccountKey.json` is only needed for the seed/backup scripts, not to run the app.
- Git push auth on Windows goes through Windows' Credential Manager (`git config credential.helper` = `manager`), shared system-wide across any git client on the machine (VS Code, terminal, Claude Code's Bash tool). If push fails with "Invalid username or token", it means no tool has authenticated yet on that machine — sign in once via VS Code's git integration (or `gh auth login`) and every other tool's pushes will then work using that same cached credential.
- Proof a deploy landed: the dist/assets JS hash changes (e.g. index-Cbm__NJd.js).
- A dev-server launch config now exists at `.claude/launch.json` (name: `dev`, runs `npm run dev` with `--port 5180 --strictPort` since port 5173 is often already occupied by a manually-started server) — use this instead of ad-hoc `npm run dev` when driving the app via Claude Code's browser preview tools.

### Correspondence (verified against `src/pages/CorrespondenceBoard.tsx` / `CorrespondenceDetail.tsx`, built 2026-08-03)
Full parity with the Risk Register pattern, on its own `correspondence` collection (see Firestore section above) — deliberately **not** siloed per-type; a single cross-cutting collection with a `type` field (`RFI`/`TQ`/`Meeting Minutes`/`Variation Request`/`Site Instruction`/`Extension of Time`/`Inspection Request`, `CORRESPONDENCE_TYPES` in `types.ts`), matching the GROUP B note below. IDs are per-type counters (`RFI-001`, `TQ-001`, ... via `nextCorrespondenceCode()` in `firestore.ts`, prefix map mirrors `nextRiskCode`'s pattern).
- **Status pipeline is non-linear** (unlike Risk's strict linear tracker): `Registered → Sent to Accountable ↔ Sent to Responsible → Completed`, plus `Obsolete` as a side-branch reachable from any stage via a separate "Mark Obsolete" button (not a track step) — `CorrespondenceStatusBar.tsx`. The Accountable/Responsible steps genuinely ping-pong (confirmed working: an item can go Accountable→Responsible→Accountable→... any number of times before Completed) by reusing `RiskStatusBar`'s existing click-any-step→confirm mechanism, which already supported clicking backward — no new logic needed there. Obsolete renders a muted banner with a "Reactivate" action that reuses the same click-to-confirm mechanism to jump back into the active track.
- **RACI-driven owner labels**: before any status change happens, "Sent to Accountable"/"Sent to Responsible" default to the *real* linked workstream's Accountable/Responsible person name (via `roles` + `pickResponsible()`), not a generic role placeholder like Risk's `STEP_OWNER` — then swap to the actual `changedBy` name once that transition occurs, same as Risk. Confirmed live: linking an item to the Civil Works workstream showed "Henning Kristensen" / "Jens Larsen" immediately, with no status change needed first.
- Recipients/involved-parties reuse Risk's existing R&R-derived plumbing directly, unchanged: `InvolvedPartiesCard`, `WorkstreamLookup`, `PersonAvatar`/`tierColor()`. **Deliberately no separate "Send Update" modal for Correspondence** — moving an item to Sent to Accountable/Responsible *is* the send action (a status-change confirm, not a compose-a-message step); can be added later if a compose box turns out to be wanted.
- Chat is **team chat only, no AI agent mode** (no Cloud Function context-builder built for Correspondence) — new `correspondence_messages` collection, `CorrespondenceChatPanel.tsx` reuses the exact same `ChatMessages`/`ChatInput` components Risk uses (their message-prop type was widened from `RiskMessage[]` to a new shared `BaseMessage` interface in `types.ts` — a minimal, non-breaking type change, not a duplicate component).
- `RiskChecklist`/`RiskNotes`/`RiskAttachments` were **not** widened/shared — Correspondence has its own `CorrespondenceChecklist`/`CorrespondenceNotes`/`CorrespondenceAttachments` (thin mirrors), consistent with how this codebase already doesn't share UI between modules. `CorrespondenceAttachments` uploads to `correspondence/{itemId}/...` in Storage via new `uploadCorrespondenceAttachment()`.
- **Bug found and fixed during this build's verification**: the shared `InvolvedPartiesCard.tsx` had a hardcoded "Involved in this risk" heading — now genericized to "Involved parties" since it's reused by both Risk and Correspondence.
- Demo seed data: `SEED_CORRESPONDENCE` in `seedData.ts` (8 items spanning all 7 types and every status incl. one `obsolete`), wired into both `src/lib/seed.ts` (client first-run seeder) and `scripts/seed.ts` (admin fresh-provision script). **Neither will backfill the already-seeded live `rtpm--v2` project** (`seedIfEmpty()` only ever runs once). A dedicated, idempotent `scripts/seed-correspondence.ts` (`npm run seed:correspondence`, needs `serviceAccountKey.json`) exists specifically to backfill it — not yet run against the live project as of 2026-08-03.
